Method

Three models, one job each

Jev is a scoring model — it cannot browse. A chat model can plan but returns prose, not a calibrated number. So each stage uses the tool that fits it.

Stage 01Plan

A small model on OpenRouter reads the resume and returns JSON: target companies and the job titles worth querying.

  • companies matched to your actual seniority
  • titles that can refer or hire — recruiters, leads, managers
  • anything you entered yourself is kept, and ordered first
  • the response is parsed, validated and clamped before use
backend/agent.py · falls back to your own input if the model is unreachable
Stage 02Source

Each company × title pair becomes one Serper query against public Google results.

  • results filtered to real /in/ profile URLs
  • canonicalized, so uk.linkedin.com/in/x/ and www…/in/x are one person
  • queries run concurrently, capped at 8 in flight
  • no LinkedIn login, no scraping, no purchased contact database
backend/search.py · public search results only
Stage 03Classify

Every candidate goes to Jev's System One endpoint with your resume attached, as two typed questions.

  • plausible_contact — a calibrated probability, not an opinion
  • priority — high, medium or low
  • combined into one 0–100 score: 0.7 × plausibility + 0.3 × priority
  • plausibility dominates; priority only breaks ties
backend/jev_client.py · a candidate that fails to score is flagged, not dropped
Stage 04Send

You write the messages. There is no sender here, deliberately.

  • every row links to the public profile so you can check it first
  • export the run as CSV and track it wherever you already work
  • automating LinkedIn outreach violates their terms and restricts accounts

Limits

What it does not do

It does not message anyone

No connect button, no DM sender, no sequencing. Automated outreach breaks LinkedIn's terms and gets accounts restricted. The list is where it stops.

It does not see private data

Everything comes from publicly indexed search results. Nothing logs in, nothing is scraped, no contact database is bought, no emails are guessed.

It is not always right

Scores are read off a search snippet, which may be stale or ambiguous. Treat the output as a shortlist to verify, not as fact about a person.
